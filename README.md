# 🌍 P2PChat

> 基于 WebRTC 的 IPv6/IPv4 端到端加密 P2P 聊天程序 —— 单个 HTML 文件，打开即用，无需任何后端服务。

## 简介

P2PChat 是一个纯前端的点对点聊天应用。整个程序只有**一个 `P2PChat.html` 文件**，双击即可在浏览器中打开使用，不依赖任何服务器、数据库或第三方运行时。两台设备各打开一份，交换一次连接码即可建立加密直连，开始聊天。

消息通过 **WebRTC DataChannel** 传输，使用 **DTLS 端到端加密**，内容不经过任何中转服务器。采用**仅直连模式**，支持 **IPv6、IPv4 以及局域网**直连。

## 特性

- 🔌 **零部署**：单文件 HTML，离线可用，打开即用。
- 🔐 **端到端加密**：WebRTC DataChannel + DTLS，消息内容第三方无法窃听。
- 🌐 **IPv6 / IPv4 / 局域网直连**：仅使用 ICE host 候选，不依赖任何 STUN/TURN，不联系任何外部服务。
- 💬 **联系人管理**：备注、IP、最近联系时间，可编辑/删除/清空记录。
- 💾 **本地持久化**：聊天记录与联系人自动保存到 `localStorage`，并支持导出/导入 JSON 备份。
- 📱 **响应式布局**：桌面端双栏，手机端单栏滑入式聊天视图。
- 🧭 **本机地址探测**：侧栏自动展示本机 IPv4 / IPv6 地址。
- ♻️ **断线自动恢复**：网络波动导致 DataChannel 断开时，若底层通道仍存活，自动尝试免交换码恢复。

## 快速开始

1. 下载 `P2PChat.html`。
2. 用 Chrome / Edge / Firefox 打开（双击即可）。
3. 两台设备（或同一台机器的两个浏览器）各打开一份：
   - **A** 点「➕ 新建连接」→ 复制**邀请码**，发给对方。
   - **B** 点「📥 接受连接」→ 粘贴邀请码 → 生成**应答码**，复制回发给 A。
   - **A** 在第 3 步粘贴应答码 → 显示「✅ 已建立加密直连」→ 开始聊天。
4. 消息自动保存；刷新页面记录仍在；可随时「⬇ 导出」/「⬆ 导入」JSON 备份。

## 连接方式说明

由于浏览器安全沙箱限制，**无法仅凭输入对方 IP 就直接发起原始连接**，因此采用 **WebRTC + 手动信令**：双方复制粘贴一次连接码完成握手，之后即建立点对点直连。

> ⚠️ **重连说明**：WebRTC 的会话信息（SDP/ICE）每次临时生成、不可复用，因此**已保存的联系人无法凭存储的 IP 自动重连**，每次重新聊天仍需双方**重新交换一次连接码**（断线自动恢复除外）。联系人列表中的 IP / 备注用于识别与整理。这是「纯无服务器」方案的固有代价。

## 仅直连模式（无 STUN）

本程序**不使用任何 STUN/TURN**，仅依赖本机 host 候选直连。因此**仅适用于以下两种场景**：

- **同一局域网**：两台设备在同一 LAN（如同一 Wi-Fi / 同一网段）。
- **双方均有公网 IP**：含全局 IPv6（`2000::/3`）或直接分配的公网 IPv4。

> ❌ **跨 NAT 的不同网络（如各自家里的宽带）无法直连**——因为没有 STUN/TURN 帮助穿越 NAT，host 候选为内网地址，无法在公网路由。这是仅直连模式的固有限制。

注意事项：
- IPv6 需为**全局地址**（`2000::/3`），`fe80::` 链路本地地址仅在同一局域网有效。
- 系统防火墙需**放行入站 UDP**（给浏览器进程加 UDP 入站规则）。
- Chrome 默认的 **mDNS 混淆**会隐藏真实本地 IP，可能导致连不上。可在 `chrome://flags/#enable-webrtc-hide-local-ips-with-mdns` 设为 **Disabled** 以暴露真实本机 IP。Firefox 默认不混淆。

## 安全说明

- ✅ **传输加密**：所有消息经 DTLS 端到端加密，网络中任何中间设备均无法解密。
- ⚠️ **信令安全**：连接码内含 DTLS 指纹与会话凭证，请通过**可信渠道**交换（当面、电话、已加密私聊），以防主动中间人攻击。
- 📌 **本地存储为明文**：聊天记录保存在浏览器 `localStorage` 和导出的 JSON 文件中，属于落盘明文，请妥善保管备份文件。
